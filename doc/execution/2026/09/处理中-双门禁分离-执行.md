# 双门禁分离（标准调用 / text2query）执行文档

> 日期: 2026-09-26
> 设计依据: `.trae/skills/text-to-query/SKILL.md`（§后端无关性与边界 L292-315）、`已完成-py-store不足清单修复-执行.md` §9/§10、工作区总纲「用户裁决权」
> 性质: 代码执行文档（AI 照此执行）
> 中心思想（用户裁定）: 普通使用功能越强越好，但**强大的前提是几个 DB 尽最大能力对齐**；DB 独有能力可用但注释须写明「不建议业务查询（维护特殊化；适合迁移/脚本）」；**text2query 必须功能收缩、硬性安全限制**；**两类场景分做不同门禁**。

## 1. 目标（验收标准）

1. core `Registry` 提供 **档位（profile）**：`standard`（默认）与 `text2query`，两档门禁不同，**判决唯一在 core**（照 `require_context` 既有范式，见 `rust-store/core/src/schema/registry.rs:17-81`）。
2. 两档差异可实测（每项有断言）：`$limit` 行数上限、关系嵌套深度、`route_override` 准入、上下文强制、DB 独有能力准入、`$pipeline` 准入。
3. **text2query 档硬限制**（相对 standard 全为收紧）：
   - 单次取数行数 ≤ `T2Q_MAX_ROWS`（含用户 `$limit` 封顶）——现 `plan_query` 对 `$limit` **无封顶**（`pipeline/util.rs:57-73` 原样下推，仅 `query_with_count` 走 `MAX_PAGE_SIZE=5000`，见 `command/query.rs:66-73`）。
   - 关系嵌套深度 ≤ `T2Q_MAX_DEPTH`，**超限显式 Err**——现超深为**静默降级空 `$lookup`**（`pipeline/lookup.rs:170-172`），违反「禁静默失守」。
   - `route_override` 一律拒绝（现仅注释警告，无运行门禁：`crud/query.py:42-55`）。
   - 强制携带用户上下文（等价 `require_context=true`，`command/mod.rs:94-99`）。
   - DB 独有能力（`$group.by` object 点号路径、`$pipeline`、`$sort` 未知字段下钻等，见 `SKILL.md:305-308`）一律拒绝。
4. **standard 档跨 DB 对齐为准**：白名单 = 四方言公共交集；交集外能力（DB 独有）**允许但须代码注释标注**（模板见 §4.5），且不得进入 text2query。
5. 所有档位拦截产出自动反馈事件 `profile_blocked`（`code=profileBlocked`，禁静默）——依据工作区总纲「自动反馈原则」。
6. 三端 parity：`py-store` / `nodejs-store` Host 面同名同义 API；`rust-store` core + 两套绑定层同步。
7. 全量回归绿：三仓库各自 lint + 单测/E2E 通过；新增档位用例覆盖上述 2~5 各一条断言。

### 4.2 core 门禁契约

```rust
// rust-store/core/src/command/mod.rs —— 档位常量 + 门禁辅助（追加在 ensure_context 邻近）
/// 档位拒绝哨兵（Host 按前缀映射为 ProfileViolation，见 §4.4）
pub const ERR_TEXT2QUERY: &str = "ERR_TEXT2QUERY:";

/// text2query 档硬限制（单点定义，Host 可读）
pub const T2Q_MAX_ROWS: f64 = 1000.0;              // 严于 MAX_PAGE_SIZE(5000)：AI 问数交互式结果规模
pub const T2Q_MAX_DEPTH: usize = 3;                // 严于 MAX_DEPTH(10)：AI 生成的关系嵌套实用上限
pub const T2Q_MAX_FEDERATION_ROWS: usize = 10_000; // 严于 MAX_FEDERATION_ROWS(100000)

/// text2query 档强制上下文（叠加于 require_context 之上）
pub fn ensure_profile_ctx(registry: &Registry, ctx: Option<&Context>) -> Result<(), String> {
    if registry.profile() == Profile::Text2Query && ctx.is_none() {
        return Err(format!("{ERR_TEXT2QUERY}text2query 档必须携带用户上下文"));
    }
    Ok(())
}

/// text2query 档禁用某项能力（standard 放行）
pub fn forbid_t2q(registry: &Registry, feature: &str) -> Result<(), String> {
    if registry.profile() == Profile::Text2Query {
        return Err(format!("{ERR_TEXT2QUERY}text2query 档禁用 [{feature}]（功能收缩）"));
    }
    Ok(())
}
```

### 4.3 绑定层契约（照 `require_context` 范式）

```rust
// registry.rs —— 档位字符串 ⇄ 枚举（单点定义；未知值 Err，禁静默回落）
impl Profile {
    pub fn as_str(&self) -> &'static str {
        match self { Profile::Standard => "standard", Profile::Text2Query => "text2query" }
    }
    pub fn from_str_or_err(s: &str) -> Result<Profile, String> {
        match s {
            "standard" => Ok(Profile::Standard),
            "text2query" => Ok(Profile::Text2Query),
            other => Err(format!("未知 profile: {other}（仅 standard / text2query）")),
        }
    }
}
```

### 步骤说明

- 步骤 1~3 在同一仓库（rust-store），可连续执行；步骤 3 是主战场，逐门禁项 verify。
- 步骤 4 是绑定层，core-py 用 `maturin`、core-node 用 `napi build` 重建后才可被 Host 调用。
- 步骤 5~6 必须在步骤 4 之后（Host 依赖绑定层的 `set_profile`）。
- 步骤 8、9 属「变强」路线（用户中心思想前半段），必须在步骤 3 之后（门禁分档先就位）。

## 7. 禁止事项

❌ 禁止把门禁判决写在 Host（py-store/nodejs-store）—— 判决唯一在 core（铁律：SQL/命令全由 core 产出，Host 只绑定参数+执行+回喂）；Host 仅做映射、反馈与兜底
❌ 禁止 `Profile::from_str_or_err` 对未知值静默回落 `Standard`（必须 Err）
❌ 禁止 text2query 档放行 `route_override`（CWE-639）
❌ 禁止在 standard 档对 DB 独有能力放行而不加 §4.5 注释块
❌ 禁止把 `$limit` 封顶只做在 `query_with_count` 路径（`plan_query` 必须同封）
❌ 禁止超深嵌套在 text2query 档继续静默降级（必须显式 Err）
❌ 禁止任一档位拦截不产反馈事件（自动反馈原则：允许拦截，禁止静默）
❌ 禁止 `git add -A` / `git add .`；账本不入库
