# py-store 多 db 联合压力测试报告

日期：2026-09-12
脚本：[stress/stress.py](../stress/stress.py)（本仓库产品 = py-store 宿主层）
运行方式：独立运行（与其他仓库压测脚本分时执行，表后缀 `py` 隔离数据）

## 1. 压测模型

四库并载（MongoDB / MySQL / PostgreSQL / SQLite），跨源 relation 联邦：

```
StressUser (Mongo) ──orders──> StressOrder (MySQL)   type: many
                  ──invoices─> StressInvoice (PG)    type: many
StressLog (SQLite) 独立写读
```

每 worker 每轮 5 操作：

| # | 操作 | 目标源 | 类型 |
|---|---|---|---|
| 1 | `query_federated` 一条 GQL 跨 3 源拉嵌套 | Mongo+MySQL+PG | 联合读 |
| 2 | `insert(StressLog)` | SQLite | 写 |
| 3 | `count(StressInvoice)` | PostgreSQL | 读 |
| 4 | `query(StressUser)` 按名字过滤 | MongoDB | 读 |
| 5 | `update(StressOrder, $inc)` | MySQL | 写 |

负载：**8 workers × 200 rounds = 8000 次操作**。

## 2. 结果

| 指标 | 值 |
|---|---|
| 总操作数 | 8000 |
| **错误数** | **0** |
| 总耗时 | 9705 ms |
| **QPS** | **824.35** |

### 2.1 全部操作延迟

| avg | p50 | p95 | max |
|---|---|---|---|
| 9.68 ms | 7.94 ms | 20.70 ms | 70.78 ms |

### 2.2 联邦查询（跨 3 源）延迟

| ops | avg | p50 | p95 | max |
|---|---|---|---|---|
| 1600 | 19.63 ms | **19.30 ms** | 24.15 ms | 70.78 ms |

## 3. 与双宿主同跑（历史第 8×200 轮）对比

| 指标 | 独立压测（本报告） | 双端同跑（历史） |
|---|---|---|
| QPS | 824.35 | 728.21 |
| 联邦 p50 | 19.30 ms | 22.60 ms |

独立压测去除了双端进程竞争，吞吐提升约 13%。

## 4. 结论

1. **稳定性**：8000 次操作 0 错误，四库并载 + 跨 3 源联邦全链路无失败。
2. **正确性**：冒烟验证联邦嵌套结果形状正确（30 用户 × orders/invoices 各 2 条）。
3. **性能**：独立压测 824 QPS；吞吐瓶颈在本机单实例数据库侧（前序双端同跑 16 workers 时 QPS 平台 ~725 已证明）。
